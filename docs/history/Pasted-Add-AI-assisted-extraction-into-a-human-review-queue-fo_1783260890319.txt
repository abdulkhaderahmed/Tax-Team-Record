Add AI-assisted extraction into a human review queue for Quarterday.

Purpose:
The AI should help convert tax documents into structured draft items, but it must never write directly into the live system-of-record registers.

Important:
AI output is draft only.
Humans must confirm, edit or reject every extracted item.
Do not create live obligations, actions, assumptions or tripwires automatically.
Do not make tax judgements.
Do not calculate tax.
Do not file anything with HMRC.

The AI should extract these item types:
1. Obligations.
2. Actions.
3. Assumptions.
4. Caveats and conditions.
5. Tripwires.
6. Evidence requirements.
7. Valuation references.
8. R&D claim references.
9. Capital allowances references.
10. Source conflicts or uncertainty flags.

Extraction should run only from documents that already exist in the document vault and have extracted text/chunks.

Create or update these database tables:

1. extraction_runs
2. review_items

1. Document.
2. Model provider.

5. Extraction schema version.
6. Started at.
7. Completed at.
8. Status: Pending, Running, Completed, Failed.
9. Error message.
10. Total chunks processed.
11. Created by.

1. Extraction run.
2. Document.

4. Item type.

9. Source page or section, if available.
10. Source text excerpt.
11. Condition text, if applicable.
12. Assumption text, if applicable.

Review status should include:
1. Needs review.
2. In review.
3. Confirmed.

5. Rejected.
6. Duplicate.

8. Needs adviser input.
9. Needs source verification.

Use strict structured output.

The AI extraction response should be validated before saving.
Use Zod or JSON schema validation.
If the AI output does not match the schema:
1. Do not save it as confirmed data.
2. Save the extraction run as failed or partially failed.
3. Show a useful error message.

The extraction schema should preserve uncertainty.

For each extracted item, the AI must identify:
1. Whether the item is definite or conditional.
2. The condition, if conditional.
3. Whether the source text says “subject to”, “provided that”, “assuming”, “based on”, “if”, “unless”, or similar.
4. Whether human tax review is required.
5. Whether source verification is required.
6. Whether the document appears to be draft or final.

The AI must not convert conditional advice into definite obligations.

Examples:
- If the document says “if the company is very large, QIPs may apply”, save this as conditional.
- If the document says “subject to confirmation of employee residence”, save the residence point as an assumption or caveat.
- If the document says “based on the facts provided”, save the relevant facts as assumptions where possible.

3. Review item type.
4. Plain English summary.
5. Source text excerpt.
6. Source page/chunk.
7. Confidence score.
8. Condition/caveat warning.

The user should be able to:
1. Confirm item.
2. Edit item and confirm.
3. Reject item.
4. Mark duplicate.
5. Mark not applicable.
6. Mark needs adviser input.
7. Mark needs source verification.
8. Link the item to an entity.
9. Link the item to an existing obligation/action/assumption.
10. Create a new live obligation/action/assumption/tripwire from the confirmed item.

When confirming an item:
1. Show the structured fields before creation.
2. Require an entity if the live object needs one.
3. Preserve the source document and source chunk/page.
4. Preserve condition text.
5. Preserve assumption/caveat links where available.
6. Create an audit event.
7. Create the live object only after confirmation.
